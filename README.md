# 学习中枢 Learning Hub

> 一个只属于你自己的外语记忆与笔记工具。
> 用网页技术做的，手机上「添加到主屏幕」后，和 App 用起来没区别。

**版本：v0.1.0** ｜ 数据 100% 存在你自己的设备上，不上传任何服务器

## 一、它现在能干什么

| 功能 | 说明 |
|---|---|
| 📝 **单张录入** | 单词 / 读音 / 释义 / 例句 / 标签，五个字段 |

## 二、怎么用

### 在电脑上打开（开发模式）

```bash
cd D:\study\learning-hub
npm run dev
```

然后浏览器打开 <http://localhost:5173>

### 在手机上打开（同一个 WiFi）

1. 电脑上跑 `npm run dev`
2. 看它输出的 `Network:` 那一行地址（现在是你这台电脑的 **`http://10.155.134.85:5173`**）
3. 手机连上**同一个 WiFi**，用浏览器打开这个地址
4. 打开后点浏览器菜单里的「**添加到主屏幕**」，桌面上就多一个图标了

> ⚠️ **电脑必须开着、`npm run dev` 必须跑着**，手机才能打开。
> 想让手机随时都能用（不依赖电脑），需要把网站放到免费的公共托管上，见下面第五节。

### 常用命令

```bash
npm run dev        # 启动开发服务器（改代码会自动刷新浏览器）
npm run build      # 打包成可以发布的文件（生成到 dist/ 目录）
npm run deploy     # 打包并发布到线上（更新 GitHub Pages）
npm run test       # 跑算法单元测试（28 项）
npm run test:e2e   # 跑端到端测试：模拟真人点界面（32 项，需先启动 dev）
npm run test:pwa   # 测试线上站点的「能装到桌面」和「断网可用」（14 项）
npm run test:all   # 前两个都跑
```

### ⚠️ 如果哪天 GitHub 突然连不上了

这台电脑遇到过一个问题：**系统 DNS 把 `github.com` 解析到了一个连不上的 IP**，导致 `git push` 和 `gh` 登录全部超时（但 `api.github.com` 是通的，所以网页能打开）。

**解决办法：以管理员身份重新运行一次这个脚本**

```
tools\fix-github-hosts.ps1
```

它会自动测一批 GitHub 的候选 IP（用真实 HTTPS 请求测，不是简单 ping），挑出当前可用的写进 hosts 文件。**GitHub 的 IP 会周期性失效，失效了就重跑一次。**

想还原系统设置，运行 `tools\undo-github-hosts.ps1`。

## 三、这个软件的三个核心设计决策

作为产品经理，你需要能解释「为什么这么做」。这三条是别人问你时最该答上来的。

### 1. 为什么是「网页」而不是「App」？

因为网页**改一次，手机和电脑同时生效**，不需要重新安装；而且不用交苹果/谷歌的开发者年费，不用等审核。
代价是：手机上不能读通讯录、不能后台常驻推送。对一个背单词工具来说，这些都不需要。

### 2. 为什么数据只存本地，不上云？

因为**第一阶段最重要的是「立刻能用」**。上云意味着要买服务器、要写账号系统、要处理登录和安全问题——这些会让第一个版本推迟好几周。
本地存储的代价是「清缓存 / 换手机会丢」，所以 v0.1 就必须有导出备份功能。

> 🔑 **产品原则：先做存档，再做功能。**
> 一个让用户丢数据的工具，功能再多也没人会留下来用。

### 3. 为什么复习算法用 SM-2？

因为它**原理公开、参数简单、效果经过几十年验证**。Anki 早期就用它。
自己发明一套「更聪明」的算法是新手最容易犯的错误——你没有几十万用户的数据来调参数。**先抄作业，再谈创新。**

## 四、项目结构（每个文件是干什么的）

```
learning-hub/
├── index.html                  网页的骨架，浏览器加载的第一个文件
├── vite.config.js              构建工具的配置（含踩坑记录）
├── package.json                项目说明书：依赖了哪些库、有哪些命令
├── .gitignore                  哪些文件不该上传（node_modules、密钥等）
├── .gitattributes              统一 Windows 与 Linux 的换行符
├── public/                     不需要打包、直接照搬的文件
│   ├── manifest.webmanifest    「安装说明书」：告诉手机这网站能当 App 装
│   ├── icon.svg                桌面图标
│   ├── sw.js                   离线缓存（Service Worker）
│   └── .nojekyll               告诉 GitHub Pages 别用 Jekyll 处理产物
├── src/
│   ├── main.jsx                入口：把 App 挂到网页上
│   ├── App.jsx                 总控：管数据、管导航、把各页面拼起来
│   ├── styles.css              全部样式（含深色模式）
│   ├── lib/
│   │   ├── db.js               ★ 数据层：把卡片存进浏览器数据库
│   │   ├── srs.js              ★ 算法层：间隔重复（这个软件的「灵魂」）
│   │   └── srs.test.mjs        算法测试（28 项）
│   └── pages/
│       ├── ReviewPage.jsx      今日复习页
│       ├── CardsPage.jsx       卡片管理页
│       ├── AddPage.jsx         录入页（单张 + 批量）
│       └── DataPage.jsx        我的 / 统计 / 备份
├── tests/
│   ├── e2e.test.mjs            端到端测试：模拟真人点界面（32 项）
│   └── pwa.test.mjs            PWA 测试：能否装到桌面、断网能否用（14 项）
├── tools/
│   ├── deploy.mjs              发布脚本（打包 + 推到 gh-pages 分支）
│   ├── fix-github-hosts.ps1    GitHub 连不上时跑它（自动挑选可用 IP）
│   └── undo-github-hosts.ps1   还原上面那个脚本的修改
├── deploy/
│   └── github-actions-example.yml  备用的自动部署配置（暂未启用）
└── screenshots/                测试自动生成的界面截图
```

> 🔑 **分层结构的意义**：`srs.js` 只管算法，`db.js` 只管存取，页面只管显示。
> 这样你想换一个更好的算法，只需要动 `srs.js` 一个文件，其它地方完全不受影响。
> 这叫**关注点分离（Separation of Concerns）**，是软件设计里最重要的一条原则。

## 五、线上地址（已上线 ✅）

# 👉 https://falao123516.github.io/learning-hub/

**手机使用方法**：用手机浏览器打开上面这个地址 → 浏览器菜单 →「**添加到主屏幕**」→ 桌面上就多一个图标，点开是全屏的，和 App 一样。

**这个地址不需要电脑开着，也不需要连同一个 WiFi。** 只要有网就能用，断网也能用（已经测试过）。

### 它是怎么发布上去的

```
你的电脑                      GitHub                      你的手机
─────────                    ────────                    ─────────
npm run deploy
   │
   ├─ 1. 打包（vite build）→ dist/
   ├─ 2. 把 dist/ 复制到临时目录
   ├─ 3. 建一个干净的 git 仓库并提交
   └─ 4. 强制推送到 gh-pages 分支 ──→ GitHub 自动把它变成网站 ──→ 打开网址就能用
```

源码在 `main` 分支，发布产物在 `gh-pages` 分支。**两个分支分开**是标准做法：源码是给人看的，产物是给浏览器看的。

**以后我每次改完功能，你或者说一句「发布一下」，我跑一条 `npm run deploy` 就更新了。**

> ⚠️ **重要**：数据存在浏览器本地，**换网址 = 数据不会跟过去**。
> 换之前先在「我的」页导出备份，新地址打开后再导入。
>
> 同一条提醒也适用于：**换浏览器**（Chrome 换成 Edge 数据不通）、**清理浏览器数据**。

### 为什么没用 GitHub Actions 自动部署

原本的方案是让 GitHub 在每次推送代码后自动打包部署。但遇到一个权限限制：

GitHub 不允许普通令牌创建或修改 `.github/workflows/` 下的文件，必须单独申请 `workflow` 权限。这不是 bug，是**故意的安全设计** —— CI 配置文件能在 GitHub 的服务器上执行任意代码、还能读取仓库密钥，如果被恶意程序偷偷改了，等于整个账号失守。

配置文件我保留在 `deploy/github-actions-example.yml`。等哪天想要「推代码就自动上线」了，跟我说一声，我带你把权限补上再启用它。

## 六、给非计算机专业的你：术语速查表

### 基础概念

| 术语 | 大白话解释 |
|---|---|
| **前端 / 后端** | 前端 = 在用户设备上跑的部分（你能看到的界面）；后端 = 在服务器上跑的部分（你看不到的算账、存数据） |
| **网页应用 / Web App** | 用网页技术做的软件。不用安装，打开网址就能用 |
| **PWA** | Progressive Web App。本质是网页，但加了「安装说明书」，可以像 App 一样装到桌面、离线用 |
| **静态网站** | 没有后端服务器的网站，所有人看到的内容都一样。非常适合免费托管 |
| **响应式设计** | 同一套代码，自动适配手机和电脑的屏幕大小 |

### 代码相关

| 术语 | 大白话解释 |
|---|---|
| **HTML / CSS / JavaScript** | 网页三件套：HTML 是骨架（有什么），CSS 是皮肤（长什么样），JS 是肌肉（能干什么） |
| **React** | 一个 JS 框架。核心思想是「把界面拆成乐高积木（组件）」，改一块不会碰坏别的 |
| **组件（Component）** | 返回界面片段的函数。比如「一张卡片」就是一个组件 |
| **状态（state）** | 组件自己管的数据。改了它，界面会自动重画 |
| **props** | 从外面传给组件的数据，组件自己不能改（像函数参数） |
| **声明式 UI** | 你只描述「界面应该是什么样」，具体怎么改由框架去算。反面是「命令式」：一步步手动改 |
| **Vite** | 构建工具。开发时提供带热更新的服务器，发布时把代码打包压缩 |
| **npm / 包管理器** | 命令行版的应用商店，用来下载别人写好的代码库 |
| **依赖（dependency）** | 你的项目用到的别人的代码库 |
| **构建（build）** | 把源码变成浏览器能高效运行的文件的过程 |

### 数据相关

| 术语 | 大白话解释 |
|---|---|
| **IndexedDB** | 浏览器内置的数据库，容量大、异步。本项目用它存卡片 |
| **localStorage** | 更简单的浏览器存储，只能存字符串、约 5MB，本项目没用它 |
| **持久化** | 把数据写到硬盘上，关了页面/重启设备还在 |
| **异步 / Promise / async-await** | 「现在还没好，等好了通知你」。像发微信（异步）而不是打电话（同步）。Promise 是提货单，async-await 是把提货单写法变好看的工具 |
| **事务（transaction）** | 一组要么全成功、要么全不做的操作。防止写到一半断电留下半截数据 |
| **数据迁移** | 软件升级后，把老格式的数据改成新格式 |
| **单一数据源（SSOT）** | 同一个信息只在一个地方是权威版本。本项目的卡片数据只由 `App.jsx` 统一管理 |

### 算法相关

| 术语 | 大白话解释 |
|---|---|
| **间隔重复（SRS）** | 根据遗忘曲线，在你快要忘的那一刻安排复习，效率远高于反复死背 |
| **记忆曲线 / 遗忘曲线** | 人忘东西先快后慢的规律，100 多年前艾宾浩斯发现的 |
| **SM-2** | 一套经典的间隔重复算法，Anki 早期用的就是它 |
| **难度系数（ease）** | 每个单词自己的难度属性。你觉得简单它就涨，你总忘它就跌 |
| **边界条件** | 算法里的「最大/最小值」限制。比如间隔最多 365 天，防止算出荒谬结果 |
| **稳健性** | 遇到脏数据（缺字段、格式错）不崩溃的能力 |

### 工程相关

| 术语 | 大白话解释 |
|---|---|
| **版本控制 / Git** | 给代码拍快照存档，改坏了能回退。像游戏的存档读档 |
| **单元测试** | 自动化检查「输入 A 应该得到 B」。算法特别需要，因为看不出对错 |
| **端到端测试（E2E）** | 用无头浏览器模拟真人点界面，验证整条链路通不通 |
| **回归测试** | 修好一个 bug 后补一条测试，防止以后改代码时它又冒出来 |
| **无头浏览器** | 没有窗口的 Chrome。照常渲染和执行 JS，只是不显示出来 |
| **乐观更新** | 先改界面再写硬盘，为了不卡顿。代价是要处理写入失败的情况 |
| **状态提升** | 把数据放到多个组件共同的父组件里统一管理，避免各存一份对不上 |
| **不可变更新** | 改数据时创建一个新对象，而不是原地修改。框架靠「对象换了没有」判断要不要重画 |
| **部署（deploy）** | 把打包好的软件发布到服务器上，让用户能用 |
| **DNS** | 互联网的「电话簿」：把 `github.com` 这样的名字翻译成 IP 地址。翻译错了就连不上 |
| **IP 地址** | 服务器在网络里的门牌号，比如 `20.200.245.247` |
| **hosts 文件** | 操作系统里一张「手写的通讯录」，优先级比 DNS 高。可以用来强制指定某个域名走哪个 IP |
| **DNS 污染** | DNS 返回了一个错误或不可达的地址。表现是「网站本身没问题，但你就是打不开」 |
| **OAuth** | 一种授权方式：让第三方工具访问你的账号，但**你的密码永远不经过它**。你点「授权」时看到的那一页就是这个 |
| **设备授权流程（Device Flow）** | OAuth 的一种，专门给没有浏览器的设备用：给你一个短码，你去浏览器里输入并确认。短码本身泄露也没关系 |
| **令牌（Token）/ 权限范围（Scope）** | 授权后拿到的「通行证」，上面写明了它能做什么。比如 `repo` 能读写代码，`workflow` 能改 CI 配置 |
| **最小权限原则** | 只申请和只授予完成当前任务必需的权限，不多要。GitHub 拒绝普通令牌改 CI 文件就是这个原则的体现 |
| **CI / CD** | 持续集成 / 持续部署：代码推上去后，服务器自动帮你测、自动帮你发 |
| **GitHub Actions** | GitHub 提供的 CI/CD 服务（配置文件在 `.github/workflows/`） |
| **分支（branch）** | 同一条代码历史的不同线。本项目 `main` 放源码、`gh-pages` 放发布产物 |
| **GitHub Pages** | GitHub 免费提供的静态网站托管。把一个分支的推上去，它就变成网站 |
| **gh-pages** | GitHub Pages 的历史默认分支名，现在成了「发布产物」的事实标准叫法 |
| **Jekyll** | GitHub Pages 默认会跑的博客生成器。它会忽略下划线开头的文件，所以放个 `.nojekyll` 让它别管 |
| **BOM** | 文件开头的一个隐藏标记，用来告诉程序「这是 UTF-8 编码」。Windows PowerShell 5.1 读脚本时非常依赖它，缺了中文就会乱码 |
| **stderr / stdout** | 程序的「正常输出」和「错误输出」两条通道。分开是为了让脚本能在只看正常输出的同时，不让错误信息污染结果 |
| **变量遮蔽（shadowing）** | 给变量起了和内置对象同名的名字（比如 `URL`），把内置的覆盖掉了。不报语法错，只在运行时炸 |
| **回归测试** | 修好一个 bug 后补一条测试，防止以后改代码时它又冒出来 |

## 七、遇到问题怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **`git push` 或 gh 命令超时** | 系统 DNS 把 `github.com` 解析到了不可达的 IP | **以管理员身份运行 `tools\fix-github-hosts.ps1`**（详见第五节） |
| **线上还是旧版本** | 忘了发布 / GitHub 还在构建 / 浏览器缓存 | 跑 `npm run deploy`，等 1 分钟，手机上强制刷新 |
| 手机打不开线上地址 | 网络问题或浏览器缓存 | 换个网络试试；清一下浏览器缓存 |
| 手机打不开 `192.168.x.x:5173` 那种地址 | 不在同一 WiFi / 防火墙挡了 / 服务没启动 | 确认同一 WiFi；确认 `npm run dev` 在跑；检查 Windows 防火墙是否允许 Node.js |
| 页面白屏 | 代码有报错 | 按 F12 打开开发者工具看 Console 标签的红色报错，截图给开发的 AI |
| 数据没了 | 清了浏览器缓存 / 卸载了主屏幕图标 / 换了浏览器 | 只能靠之前的备份导入。**所以请养成定期导出备份的习惯** |
| 端口 5173 被占用 | 上次的服务器没关干净 | 换个端口：`npm run dev -- --port 5174` |
| 改了代码浏览器没变 | 浏览器缓存 | 强制刷新：电脑上 `Ctrl + Shift + R` |

### ⚠️ 三条关于数据的铁律

1. **换网址、换浏览器、清缓存 = 数据全没了。** 数据只存在那一个浏览器里，不跟人走。
2. **每次学会一批新词，就去「我的」页导出一次备份**，文件存微信收藏或网盘。
3. **做任何「清理」「重置」「恢复出厂」操作之前，先导出备份。**

## 八、想加功能的话，直接这样说

你不用学写代码，但**把需求说清楚**本身就是产品经理的核心技能。好的需求描述包含这四样：

1. **谁在什么场景下** —— 「我在地铁上背单词的时候」
2. **想做什么** —— 「想只复习那些我经常忘的词」
